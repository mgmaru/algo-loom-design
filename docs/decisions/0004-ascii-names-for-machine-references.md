# ADR-0004 機械が参照する名前を英語にし、CIのjob名を改める

| 項目 | 内容 |
|---|---|
| 状態 | 採用 |
| 日付 | 2026年9月19日 |
| 関連TODO | ―（TODOに属さない判断） |
| 正本 | [表記規則 §1](../project/writing-conventions.md)、[workflow](../../.github/workflows/checks.yml)、GitHubのRuleset設定 |

## 背景と前提

[ADR-0002](0002-ci-and-branch-policy.md)で導入したCIは、jobの表示名を日本語（`文書と検証物`、`判断の確認`）にしていました。[ADR-0003](0003-protect-main-with-ruleset.md)でRulesetを適用したとき、この表示名が**status checkの名札**としてRulesetから文字列で参照される構造になりました。

判断の土台にした事実です。

| # | 前提 | 根拠 |
|---|---|---|
| 1 | job名はRulesetから文字列で突き合わせられる | Rulesetに保存された名札とworkflowのjob名が、UTF-8のbyte列で完全一致していることを2026年9月19日に実測した |
| 2 | 名札が一致しないと、checkは失敗ではなく**未報告**として扱われ、PRが永久にmergeできない | [ADR-0003](0003-protect-main-with-ruleset.md)へ落とし穴として記録済み |
| 3 | このリポジトリでは、機械が参照する名前は英語、人が読む出力は日本語で書かれてきた | test名は`TestProtocolHappyPathAndOneTimeCapture`等の英語、`check-docs.mjs`の出力は日本語 |
| 4 | 表記規則は「実装と対応付ける必要がある名前まで訳すと、コードと文書の対応が失われる」と定めている | [表記規則](../project/writing-conventions.md) |
| 5 | 日本語は表記の揺れ（正規化、全角半角）が起こりうる文字種である。ASCIIにはその失敗モードがない | 一般的な性質 |

技術的に壊れてはいませんでした。前提1のとおり一致しており、PR #2とPR #3はどちらも通っています。**動かないから変えるのではなく、失敗したときの影響と、規則との不整合を理由に変えます。**

## 決定

1. **機械が参照する名前は英語にします。** 表示用に見えても、他の設定から文字列で参照されるなら英語です。この規則を[表記規則 §1](../project/writing-conventions.md)へ追加しました
2. **人が読むだけの表示は日本語のままにします。** CIのstep名、スクリプトの出力メッセージが該当します
3. CIのjob名を次のとおり改めます。Rulesetの名札も同じ値へ更新しました

| job id | 変更前の名札 | 変更後の名札 |
|---|---|---|
| `documents` | `文書と検証物` | `documents-and-verification` |
| `decision` | `判断の確認` | `decision-record` |

4. **適用の順序を「Rulesetを先、workflowを後」とします。** 逆順では、PRのcheckが新しい名札で報告される一方Rulesetが古い名札を待つため、そのPR自体が通らなくなります

## 検討して採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| 日本語の名札のままにする | 前提4の規則に反する。前提5のとおり、一致に失敗したときの症状（PRが永久に止まる）に対して、得られる読みやすさが釣り合わない |
| jobの`name:`を削除し、job idを名札にする | 名前が1箇所で済む利点はあるが、**`name:`を省略したときの表示は公式docsに記載がない。** 検証していない挙動にPRの可否を賭けない |
| まとめ役のjobを1つ置き、Rulesetはそれだけを必須にする | Rulesetを触らずjobを増減できる利点がある。ただし`main`へのpushでは`decision`がskipされるため、まとめ役がskipを成功として扱う判定を正しく書く必要があり、**落とし穴を別の場所へ移すだけになる。** jobが2つしかない現状では利点が小さい |

## 理由

2つあります。

第一に、**規則との不整合を解消できます。** 表記規則は既に「実装と対応付ける必要がある名前は英語」と定めており、job名はまさにそれに当たります。規則の側を変えるのではなく、規則の適用範囲を明示するほうが一貫します。

第二に、**失敗の代償に見合いません。** 日本語でも動きますが、一致に失敗したときPRは「失敗」ではなく「待ち続ける」状態になります。原因に気づきにくく、ASCIIならその種の揺れ自体が起きません。

## 影響と再評価条件

- [ADR-0003](0003-protect-main-with-ruleset.md)に記録した名札の値（`文書と検証物`、`判断の確認`）は、この決定で置き換わりました。**ADR-0003の本文は書き換えていません。** 決定記録は判断した時点の記録であり、現在のRulesetの正本はGitHubの設定です
- job名を変えるときはRulesetの名札も同じ変更で直す、という制約は変わりません

次のいずれかが起きたら見直します。

- **jobが増えて入れ替わりが頻繁になったとき。** まとめ役のjobを置く案へ移り、Rulesetが持つ名札を1つに減らします
- **`name:`省略時の挙動が公式に文書化されたとき。** `name:`を削除して名前を1箇所に減らせます
