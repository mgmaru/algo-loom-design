## ドキュメント概要

本書は、決定記録（ADR）の一覧と書き方を定めます。ADRは**判断した時点の記録**であり、後から書き換えません。現在の仕様が知りたいときは`docs/`の各文書を、判断が必要な未決事項は[未決事項一覧](../project/unresolved-decisions.md)を参照します。

## 用語

| 語 | 意味 |
|---|---|
| ADR | Architecture Decision Record。一つの判断について、背景、前提、決定、理由、影響を記録したもの |
| 前提 | 判断の土台にした事実または仮定。**後から「その前提が誤りだったか」を評価するために書きます** |
| 置換済み | 後のADRが同じ主題について別の判断をした状態。旧ADRは残し、削除しません |

## 何をADRにするか

次のいずれかに当てはまる判断を書きます。

- 製品の契約、保存する内容、外部作用の範囲が変わる
- 採用しなかった選択肢がある
- 前提が変われば覆りうる
- 後から「なぜこうなっているのか」を問われる

逆に、次は書きません。作業記録や仕様の説明であり、判断ではないためです。

- 作業の実施記録（検証記録は`docs/verification/`、作業の進行は[TODO.md](../../TODO.md)）
- 現在の仕様そのもの（`docs/`の各文書が正本）
- credential、実account名、固定ID等（[作業ガイド](../../CLAUDE.md)の禁止事項に従います）

## 書き方

- **1つの決定につき1ファイル**とし、`NNNN-<英語のslug>.md`の名前にします。番号は追加順の連番です
- **番号をTODOのIDと一致させません。** 一つのTODOが複数の決定を生み、一つの決定が複数のTODOにまたがるためです（[ADR-0001](0001-adopt-decision-records.md)）
- **本文を書き換えません。** 誤字の修正を除き、内容の変更は新しいADRで行います
- 判断が変わったら新しいADRを書き、**旧ADRには状態と行き先のリンクだけ**を追記します
- 関連するTODOがあれば、ADRの「関連TODO」と[TODO.md](../../TODO.md)一覧表の「決定」列の**両方**へ書きます。片側だけの記載は`node scripts/check-docs.mjs`が検出します

## 書式

```text
# ADR-NNNN <決定を一文で>

| 項目 | 内容 |
|---|---|
| 状態 | 採用 / 置換済み（→ ADR-NNNN） / 撤回 |
| 日付 | YYYY年M月D日 |
| 関連TODO | TD-NN、TD-NN / ― |
| 正本 | 現在の仕様がある文書への相対path |

## 背景と前提

何を解こうとしたか。判断の土台にした事実と仮定を、後から検証できる形で書く。

## 決定

何を決めたか。

## 検討して採らなかった案

案と、採らなかった理由。

## 理由

なぜそう決めたか。

## 影響と再評価条件

何が変わるか。どの前提が崩れたら見直すか。
```

「背景と前提」を必ず書きます。**判断が誤っていたかどうかは、前提と実際に起きたことを突き合わせて判定するため**、前提のないADRではその評価ができません。
