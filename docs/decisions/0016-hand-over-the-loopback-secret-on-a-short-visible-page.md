## 背景と前提

認証ヘルパーは、拡張機能と通信するために**待受番号**と**一回限りの秘密値**を作ります。拡張機能はこの2つを知らなければ認証ヘルパーへ連絡できません。**この受け渡しを「初期化」と呼びます。**

初期化は現在、`http://127.0.0.1:<待受番号>/bootstrap`のページを経由しています。検証物ではこのページが同意画面を兼ねており、利用者にボタンを押させます。**製品では同意は初回だけのため、2回目以降にこの画面をどう扱うかが決まっていませんでした。**

判断の土台にした事実です。

| # | 前提 | 根拠 |
|---|---|---|
| 1 | 待受番号は`127.0.0.1:0`で開いてOSに割り当てさせるため、**実行のたびに変わる** | [`helper/main.go`](../../scripts/verification/atcoder_v12/helper/main.go)、[`helper/submit_entry.go`](../../scripts/verification/atcoder_v12/helper/submit_entry.go) |
| 2 | 一回限りの秘密値は32バイトの乱数を16進64桁にしたもので、**実行のたびに作り直す** | 同上（`randomHex(32)`） |
| 3 | 認証ヘルパーは窓口へ来たrequestを4つで検査する。`Host`、接続元が`127.0.0.1`か、`Origin`が`chrome-extension://<固定ID>`か、Bearerの秘密値が一致するか | [`helper/protocol.go`](../../scripts/verification/atcoder_v12/helper/protocol.go) |
| 4 | 拡張機能は、秘密値をページの`<meta name="algoloom-loopback-token">`から、待受番号を`location.port`から読み、**読んだ直後にmetaを削除する** | [`extension/bootstrap.js`](../../scripts/verification/atcoder_v12/extension/bootstrap.js)、[`helper/consent.html`](../../scripts/verification/atcoder_v12/helper/consent.html) |
| 5 | 受け取った値は`chrome.storage.session`へ入る。**browserを閉じると消える** | [`extension/service_worker.js`](../../scripts/verification/atcoder_v12/extension/service_worker.js) |
| 6 | 実行のたびに使い捨てのprofile複製でbrowserを起動する。したがって`chrome.storage.session`は毎回空で、**受け渡しは実行ごとに要る** | [AtCoder認証設計 §3.3](../architecture/atcoder-authentication.md#33-ブラウザ境界)、[UX設計 §4](../project/atcoder-authentication-manual-operation-automation.md#4-chromeプロファイルの寿命) |
| 7 | **受け渡し自体はページの読み込みで完了する。** content scriptは読み込み時に動く。押す操作は同意のためだけにある | 前提4と同じ |
| 8 | 製品の同意は初回だけで、取得対象・用途・保存先・権限が変わるまで再確認しない | [AtCoder認証設計 §3.2](../architecture/atcoder-authentication.md#32-利用者の導線)、[UX設計 §3.2](../project/atcoder-authentication-manual-operation-automation.md#32-submitからの再認証) |
| 9 | 仕様は、途中のcopy-and-paste、手動ページ移動、追加のYes/No確認を求めないことを要件にしている | [`F-SUBMIT-01` R10](../../spec/features.md#81-atcoder認証状態確認f-submit-01) |
| 10 | 認証ヘルパーは常駐しない。**認証1回ごとに起動して終了する** | [AtCoder認証設計 §1.2](../architecture/atcoder-authentication.md#12-認証ヘルパーとは何か)、[性能と待ち時間設計](../quality/performance-and-waiting-design.md)、[Core契約](../architecture/core-contracts.md) |
| 11 | 検証物では同じ画面が同意を兼ね、クリックを求める。同意版の検査が`V-12`の合格条件に入っているため | [検証物README](../../scripts/verification/atcoder_v12/README.md)、[ADR-0011](0011-add-submit-entry-before-rerunning-v12.md) |
| 12 | 拡張機能へ値を渡す他の手段は、権限の追加か利用者の環境変更を伴う。`nativeMessaging`は要求せず、企業向けポリシーとOSの設定は変更しない | [AtCoder認証設計 §8](../architecture/atcoder-authentication.md#8-採用しない前提と方式)、[拡張機能の責任境界 §2.3](../features/extension-boundary-and-degraded-submission.md#23-拡張機能側で固定する項目) |

**前提6と前提10は表裏です。** 常駐しないことの代償として、受け渡しが実行のたびに発生します。

## 決定

1. **初期化の受け渡しは、いま何をしているかを示す短い画面で通します。** 利用者から見えるところで行い、説明を付けます
2. **この画面でクリックを求めません。** 受け渡しは読み込みで完了するため、押させる理由がありません（前提7）
3. **この画面で同意文面を再掲しません。** 同意は初回だけです（前提8）
4. **認証ヘルパーを常駐させて受け渡しを1回で済ませる案は採りません**（[§検討して採らなかった案](#検討して採らなかった案)）
5. このADRで決めるのは「**見える・説明がある・押させない**」の3点だけです。文言、表示時間の下限、遷移に失敗したときの見せ方は[`TD-55`](../../TODO.md#td-55-初期化画面の表示と文言を確定する)で確定します
6. **検証物は現在の形（同意を兼ねた画面）のままにします。** `V-12`の合格条件が同意版の検査を含むためで、製品と検証物で形が違うことを記録として残します

## 検討して採らなかった案

| 案 | 採らなかった理由 |
|---|---|
| **A 説明を付けず、一瞬だけ表示する** | 利用者に「いまのは何だったのか」が残る。**説明できない画面を出すことは、外部作用を利用者の明示操作へ結び付けるという契約を、体感の側から崩す。** 操作数は案Bと同じで、得るものがない |
| **C 見えないタブで受け渡す** | tabが勝手に増減し、**browserが裏で動いている**という印象になる。受け渡しに失敗したときも利用者が気づけず、「browserが開いたのに何も起きない」状態（[縮退運転設計 §3.2](../features/extension-boundary-and-degraded-submission.md#32-事前に検知する)が避けると決めた状態）へ近づく |
| **認証ヘルパーを常駐させ、受け渡しを1回で済ませる** | 受け渡しの回数は減るが、**窓口と秘密値の寿命が延びる。** `127.0.0.1`の窓口は同じ端末のどのプログラムからも叩けるため、開いている時間がそのまま狙われうる時間になる。秘密値を「一回限り」にできるのも短命だからである。加えて、**暗黙に動くものを作らない**という方針（前提10）に反する |
| **待受番号を固定する** | 他のソフトと衝突する。番号が知られていると、**同じ端末の別プログラムが先回りしてその番号で待ち構えられる** |
| **`nativeMessaging`で渡す** | 拡張機能の権限が増える。単一目的と最小権限の説明が崩れ、審査で説明すべき範囲も広がる（前提12） |
| **企業向けポリシーまたは管理下のstorageで渡す** | 利用者の環境（OSの設定）を書き換えることになり、**所有境界を越える**（前提12） |
| **AtCoderのURLへ秘密値を載せて渡す** | 秘密値がAtCoder側のページ、履歴、`Referer`へ流れうる。**秘密を渡すために秘密を漏らす経路を作ることになる** |
| **同意画面を毎回出して、そこで受け渡す** | 前提8の契約に反する。押す操作が毎回増え、`F-SUBMIT-01` R10の「追加のYes/No確認を求めない」とも食い違う |
| **受け渡しをやめ、提出フォームの知識を拡張機能へ持たせる** | 認証ヘルパーへ問い合わせる必要がなくなるが、**AtCoderが提出フォームを変えるたびにChrome Web Storeの審査が必要になる**（[拡張機能の責任境界 §2.5](../features/extension-boundary-and-degraded-submission.md#25-この境界で何が変わるか)）。追随の速度を失う |

## 理由

3つあります。

第一に、**見えるものには説明を付けます。** 一瞬でも画面が出るなら、それが何かを言えるようにします。説明のない画面は、利用者に「勝手に動いている」と読ませます。AlgoLoomは外部作用を利用者の明示操作へ結び付けることを中心の約束にしているため、**体感の側でその約束を崩す形を選びません。** 案Aと案Cが落ちるのはこの一点です。

第二に、**毎回の受け渡しは、寿命を短くした代償です。** 常駐させれば受け渡しは1回で済みますが、窓口と秘密値が開きっぱなしになります。**代償を消すのではなく、代償を利用者から見て意味のある1行に変えるのが案Bです。** 「準備しています」と示すことで、毎回の遷移が説明のつく挙動になります。

第三に、**押させないことを、確かめたうえで決めています。** 受け渡しはcontent scriptが読み込み時に`<meta>`と`location.port`を読むことで完了します（前提4、7）。クリックを外しても機能は失われません。**仕様の「追加のYes/No確認を求めない」と、実装の作りが一致していることを確認したうえでの決定です。**

## 影響と再評価条件

- **提出のたびに短い画面が1枚挟まります。クリックは増えません。** 利用者の操作は、AtCoderの提出ボタン1回（＋Turnstileが出れば操作）のままです
- 仕様と[UX設計](../project/atcoder-authentication-manual-operation-automation.md)へ、初期化画面の扱いを書き足す作業が要ります（[`TD-55`](../../TODO.md#td-55-初期化画面の表示と文言を確定する)）
- **このADRは、再認証を伴わない提出で誰がローカル処理を起動するかを決めていません。** [AtCoder認証設計 §1.2](../architecture/atcoder-authentication.md#12-認証ヘルパーとは何か)は認証ヘルパーを認証時だけ起動すると書き、[拡張機能の責任境界 §2](../features/extension-boundary-and-degraded-submission.md#2-拡張機能の責任境界)は提出フォームへの指示・提出IDの取得・判定確認を認証ヘルパーの担当としています。**2つが噛み合っていません。** [`TD-56`](../../TODO.md#td-56-再認証を伴わない提出でローカル側の処理を誰が起動するかを確定する)で扱います
- 検証物は変えません。helperのbuild hashは動かず、`V-12`の合格に影響しません

次のいずれかが起きたら見直します。

- **表示が短すぎて読めない、またはちらつくと実測で分かったとき。** 表示時間の下限か、画面の出し方を決め直します
- **[`TD-40`](../../TODO.md#td-40-提出ページのcontent-scriptとturnstileの共存を検証する)で提出ページの構成が変わったとき。** 初期化を置く位置が変わりえます
- **権限を増やさずに値を渡せる公式の手段が使えるようになったとき。** 画面そのものを無くす判断があり得ます
- **別の理由で常駐が必要になったとき。** そのときは窓口と秘密値の寿命をどう抑えるかを決め直します
