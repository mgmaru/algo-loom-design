# AlgoLoom ライブラリ選定記録

> 対象: AlgoLoomのMVP実装で使用するライブラリと外部ツールの採否
>
> 状態: 進行中。`online-judge-tools`の採否は決定済み。共通の選定基準とその他の対象は`TD-25`、`TD-26`で追記する
>
> 決定日: 2026年8月24日
>
> 正本: 製品の範囲と契約は[MVPスコープ](../product/mvp.md)および[Core契約](../architecture/core-contracts.md)を優先する。本書は、その契約を満たすために工程4で行ったライブラリ選定の判断と根拠を記録する

## ドキュメント概要

本書は、選定対象、共通の選定基準、対象ごとの採否、根拠、再評価条件を一か所で追跡します。ライブラリの既定動作を製品の挙動として採用せず、既存の製品契約を弱めずに実装できるかを判断します。

## 0. 結論

`online-judge-tools`は、初期の`JudgeAdapter`実装には採用しません。AtCoderとの通信は、送信先、HTTPメソッド、回数、間隔、上限、リダイレクト、自動再試行、保存項目をAlgoLoom側で明示できる、薄い自作HTTPアダプタとして実装します。

| 選定対象 | 対象範囲 | 採否 | 初期実装の方針 |
|---|---|---|---|
| `online-judge-tools` | AtCoder向け`JudgeAdapter`の初期実装 | 不採用 | 薄い自作HTTPアダプタを`JudgeAdapter`境界の後ろへ置く |

この判断は、`JudgeAdapter`の交換可能性をなくすものではありません。将来の候補が製品契約と共通の選定基準を満たし、契約テストに合格した場合は、境界の内側の実装として再評価できます。ライブラリ名、HTTP応答の生形式、外部ツールの終了コードを、ドメインまたは保存スキーマの契約にはしません。

## 1. 本書の責任

### 1.1. 本書で決めること

- 工程4で選定するライブラリと外部ツールの対象一覧
- 対象ごとの採否、根拠、採用範囲、再評価条件
- 選定結果が製品契約を弱めないための境界

### 1.2. 本書で決めないこと

- クラス、モジュール、依存性注入の最終構成
- ライブラリの初期化方法、ファイル配置、ビルド設定
- AtCoderへのアクセスまたは配布が許可される範囲
- 未完了の対象について、比較前に候補や採否を固定すること

AtCoderへのアクセスと配布の条件は、[公開情報に基づく配布判断](atcoder-public-policy-review.md)と[未決事項8.1](unresolved-decisions.md#81-公開情報に基づく配布判断と再確認gate)に従います。本書の技術的な採否や実サービスでの成立を、AtCoderから許可を得た事実とは扱いません。

## 4. 共通の選定基準

共通の足切り基準と評価観点は`TD-25`で追記します。`TD-05`では、`online-judge-tools`だけを、すでに確定している次の必須条件で評価します。

| 必須条件 | 根拠 |
|---|---|
| 入出力例取得、アカウント確認、提出、提出ID取得、判定確認を`JudgeAdapter`の契約へ射影できる | [MVPスコープ §3.3](../product/mvp.md#33-mvpの依存関係)、[技術検証計画 §3](judge-adapter-verification.md#3-検証項目) |
| パスワード入力型ログインを通常導線にせず、方式Aで確立したセッションを使用できる | [AtCoder認証設計](../architecture/atcoder-authentication.md) |
| 接続、リクエスト、ポーリング全体の上限、自動再試行、間隔をAlgoLoom側で制御できる | [`V-09`の合格記録](../verification/judge-adapter/results/2026-08-12-p0-22.md) |
| 外部ツールの出力や生のHTMLをそのままCoreまたは履歴へ保存しない | [MVPスコープ §3.3](../product/mvp.md#33-mvpの依存関係) |
| MVPのPython実行環境で起動でき、利用者が求めていない通信を行わない | [技術検証の実施手順 §10](../verification/judge-adapter/README.md#10-事前調査で判明した注意点) |

## 5. `online-judge-tools`の採否

### 5.1. 判断

| 項目 | 内容 |
|---|---|
| 採否 | **初期の`JudgeAdapter`実装には不採用** |
| 不採用の範囲 | `oj`コマンドを主要導線の実装として呼び出すこと、および同ツールの既定動作を製品の挙動として採用すること |
| 代替方針 | 薄い自作HTTPアダプタを`JudgeAdapter`境界の後ろへ置く |
| 判断の性質 | 初期実装の選択。ドメイン、保存スキーマ、恒久的な外部契約にはしない |

### 5.2. 技術検証で確認した事実

| 観点 | 観測事実 | 根拠 |
|---|---|---|
| PyPIの公開版 | 最新版は`11.5.1`で、公開日は2021年9月13日 | [技術検証の実施手順 §10](../verification/judge-adapter/README.md#10-事前調査で判明した注意点)、[PyPIの配布記録](https://pypi.org/project/online-judge-tools/) |
| Python 3.12 | Python 3.12.13では`distutils.version`の読み込みに失敗し、`oj`が起動しなかった | [技術検証の実施手順 §10](../verification/judge-adapter/README.md#10-事前調査で判明した注意点) |
| 起動時の通信 | `oj --version`でもPyPIへの更新確認が発生した | [技術検証の実施手順 §10](../verification/judge-adapter/README.md#10-事前調査で判明した注意点) |
| アカウント確認 | `oj login --check`はログイン状態を返すが、アカウント識別情報を返さない | [`p0-02`](../verification/judge-adapter/results/2026-08-11-p0-02.md) |
| 判定確認 | `oj-api`の公開コマンドには提出IDを指定する判定取得がなく、Python APIの提出詳細取得は非推奨かつ未実装だった | [`p0-17`](../verification/judge-adapter/results/2026-08-12-p0-17.md) |
| 提出一覧 | Python APIの提出一覧反復は、ページ上限を渡さない場合に後続ページを走査し得る | [技術検証の実施手順 §10](../verification/judge-adapter/README.md#10-事前調査で判明した注意点) |
| 認証 | パスワード入力型CLIで認証済みセッションを確立できず、Turnstileの存在を確認して回避せず停止した | [`p0-02`](../verification/judge-adapter/results/2026-08-11-p0-02.md) |

2026年8月24日に公式情報を再確認しました。PyPIの最新版は引き続き`11.5.1`です。公式リポジトリの[リリース`v12.0.0`](https://github.com/online-judge-tools/oj/releases/tag/v12.0.0)では`distutils`の削除とPython最低バージョンの変更が行われていますが、PyPIの最新版にはなっておらず、AlgoLoomの技術検証でも実サービスの主要導線を確認していません。また、AtCoderのCloudflare導入後のログイン失敗を扱う[Issue #934](https://github.com/online-judge-tools/oj/issues/934)は同日時点で未解決です。したがって、新しいリポジトリ版が存在することだけを、初期実装へ採用する根拠にはしません。

### 5.4. 不採用の理由

| 理由 | 判断 |
|---|---|
| 主要導線の不足 | 入出力例取得の一部だけでは足りず、アカウント識別、提出ID指定の判定確認、状態不明の保持を含む主要導線を公開入口だけで満たせない |
| 認証境界の不一致 | パスワード入力型ログインはMVPで採用せず、検証でも成立しなかった。方式Aのセッション取得と保管は独立した境界として実装する必要がある |
| 通信制御の不足 | 標準のログイン経路では接続上限、リクエスト上限、開始間隔を分けて設定できず、バージョン表示でも利用者が求めていない更新確認が発生した |
| 実行環境と配布の不一致 | 検証したPyPI版はPython 3.12で起動せず、新しいリポジトリ版はPyPI版としてもAlgoLoomの実サービス検証結果としても扱えない |
| 成立した代替経路 | 全11項目は、対象と上限を限定した薄い経路で合格し、必要な状態を許可リストへ射影できた |

### 5.5. 薄い自作HTTPアダプタの境界

初期実装では、検証支援コードを複製して製品コードにしません。匿名化済み実行記録の観測事実と、設計文書および`spec/`の契約を入力として、製品用の実装とテストを新たに作ります。

| 責任 | 初期実装で満たすこと |
|---|---|
| 通信範囲 | 必要な送信先、HTTPメソッド、対象問題または提出ID、最大件数を操作ごとに固定する |
| 有限性 | 接続、リクエスト、ポーリング全体の上限を分離し、自動再試行を既定で行わず、サーバーの待機指示を尊重する |
| 認証 | 方式Aの認証セッション境界から、本人確認に必要なセッションだけを実行時に受け取る。パスワードを受け取らない |
| データ境界 | 生のHTML、生のヘッダー、秘密情報を保存せず、許可した項目、型、単位、欠損、状態だけへ射影する |
| 部分失敗 | 送信前失敗、送信後の状態不明、判定待ち、最終判定を区別し、再起動後も同じ提出IDを再確認できるようにする |
| 依存方向 | `JudgeAdapter`境界の内側へ閉じ込め、Core、ドメイン、保存スキーマをAtCoderのHTML構造またはライブラリ固有型へ依存させない |

### 5.6. 再評価条件

将来`online-judge-tools`または別の候補を再評価する場合は、少なくとも次をすべて確認します。

- 対象とする配布版を固定し、MVPのPythonと3つの対象OSで起動できる。
- 起動時と通常操作で、利用者が求めていない外部通信を行わない。
- 方式Aの認証境界を弱めず、パスワード入力型ログインや平文の認証情報保存を要求しない。
- アカウント識別、提出IDの取得、同じ提出IDの判定再確認、状態不明を安定した型へ射影できる。
- 接続、リクエスト、ポーリング全体の上限、待機間隔、リダイレクト、自動再試行をAlgoLoom側で制御できる。
- 生のHTML、ヘッダー、例外文、ツール固有型をCoreまたは履歴へ漏らさない。
- 固定入力の契約テストと、明示承認された最小限の実サービス確認に合格する。

条件を満たしても自動的に採用へ変更せず、本書へ新しい判断として記録します。
